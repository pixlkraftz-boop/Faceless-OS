# AGENT_RULES

## PURPOSE

AGENT_RULES defines how autonomous AI agents are allowed to modify, expand, and maintain FacelessOS.

The purpose of this file is to ensure:

- stable evolution
- architectural consistency
- workflow coherence
- overlay integrity
- non-destructive iteration

during agentic development.

Agents should treat FacelessOS as:

an evolving creative infrastructure system.

NOT as disposable prompt documentation.

---

## CORE PRINCIPLE

Agents must prioritize:

- stability
- clarity
- modularity
- continuity
- compatibility

over unnecessary expansion.

The goal is sustainable evolution.

NOT uncontrolled complexity growth.

---

## INHERITANCE RULES

Agents must respect all inheritance chains.

Before modifying any file,
agents must identify:

- inherited systems
- dependent workflows
- affected overlays
- linked execution layers

Agents must never:

- silently break inheritance
- orphan workflows
- remove required dependencies
- duplicate inherited logic

---

## MODIFICATION PRINCIPLE

Agents should prefer:

- extending existing systems
- patching workflows
- refining current logic

instead of:

- creating redundant files
- duplicating workflows
- adding overlapping systems

The repo should evolve:

carefully,
not explosively.

---

## FILE CREATION RULES

New files should only be created when:

- a genuinely new production capability is required
- an existing workflow becomes overloaded
- a reusable system clearly emerges
- production friction repeatedly appears

Agents should avoid:

- unnecessary abstraction
- philosophical duplication
- excessive orchestration complexity
- speculative architecture expansion

---

## NAMING CONVENTIONS

Agents must preserve naming consistency.

Examples:

### ENGINES
- HUMAN_TEXTURE_ENGINE
- TOPIC_DISCOVERY_ENGINE

### WORKFLOWS
- TOPIC_TO_SCRIPT
- VISUAL_BEAT_MAPPING

### OVERLAYS
- CRUDE_LORE
- DEAD_GAME_ARCHIVE

### EXECUTION_LAYERS
- VIDRUSH

Names should remain:

- descriptive
- modular
- stable
- machine-readable

---

## UPDATE RESPONSIBILITIES

When modifying a system,
agents must evaluate:

- dependent workflows
- affected overlays
- inheritance references
- retrieval logic
- compatibility implications

If a change affects another file,
agents should update it automatically.

---

## COMPATIBILITY PRINCIPLE

New systems must remain compatible with:

- existing overlays
- workflows
- retrieval systems
- execution layers
- documentary philosophy

Agents must avoid:

- identity-breaking modifications
- incompatible orchestration
- contradictory pacing systems
- retrieval-hostile logic

---

## DOCUMENTARY PRIORITY

FacelessOS exists primarily for:

- documentary production
- cinematic explainers
- investigative storytelling
- retrieval-safe scripting
- AI-assisted video generation

Agents should preserve this focus.

The repo should not drift toward:

- generic content creation
- social media spam
- trend farming
- unrelated automation systems

---

## OVERLAY PROTECTION

Overlays represent persistent editorial identities.

Agents must preserve:

- tonal integrity
- pacing philosophy
- visual identity
- audience psychology
- packaging style

Agents must avoid:

- overlay homogenization
- identity contamination
- cross-overlay tonal drift

---

## RETRIEVAL PROTECTION

Agents must preserve:

- visual retrievability
- scene continuity
- environmental grounding
- cinematic sequencing

especially for:

- Vidrush
- AI image generation
- AI video systems
- stock retrieval workflows

Agents should reject modifications that weaken:

- visual density
- physical specificity
- cinematic progression

---

## PRODUCTION PRIORITY

Agents should prioritize building systems that improve:

- production speed
- output quality
- narrative coherence
- packaging strength
- retrieval quality
- visual pacing
- editorial consistency

Production leverage is prioritized over theoretical complexity.

---

## REFACTORING PRINCIPLE

Agents are encouraged to:

- simplify systems
- reduce duplication
- improve clarity
- consolidate overlapping logic

when appropriate.

The repo should gradually become:

- cleaner
- smaller
- more powerful
- easier to evolve

over time.

---

## FAILURE MODES

Agent failure includes:

- architectural bloat
- redundant systems
- broken inheritance
- identity drift
- retrieval collapse
- overlay contamination
- philosophical duplication
- over-engineering

Agents should actively avoid complexity addiction.

---

## COMMIT PHILOSOPHY

Commits should remain:

- small
- clear
- modular
- reversible
- understandable

Agents should avoid:

- massive uncontrolled rewrites
- chaotic structural changes
- undocumented modifications

---

## LONG-TERM VISION

FacelessOS is intended to evolve into:

an AI-readable documentary production infrastructure layer.

Agents should optimize for:

- future automation
- autonomous iteration
- creative decision support
- production orchestration
- editorial intelligence

NOT static documentation.

---

## ENFORCEMENT

Agents must reject:

- AI slop systems
- engagement farming
- rage optimization
- low-trust content systems
- generic content automation
- architectural chaos

Editorial integrity remains mandatory.

---

## CORE PRINCIPLE

Agents exist to evolve FacelessOS carefully and intelligently.

Not endlessly expand it.
