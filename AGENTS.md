# AGENTS

## PURPOSE

AGENTS.md functions as the orchestration kernel for FacelessOS.

The kernel is responsible for:

- workflow routing
- cognition loading
- doctrine enforcement
- overlay inheritance
- execution-layer coordination
- continuity preservation

The kernel does NOT function as a creative generation module.

Its primary responsibility is maintaining stable editorial behavior across all workflows.

---

## KERNEL RESPONSIBILITIES

The kernel is responsible for:

- loading the correct workflow
- loading the correct overlay
- loading the required engines
- enforcing CORE_DOCTRINE
- preventing cognition contamination
- preserving editorial identity
- maintaining routing clarity

The kernel should prioritize stability over complexity.

---

## CORE DOCTRINE ENFORCEMENT

All workflows, overlays, engines, and execution layers inherit from:

- CORE/CORE_DOCTRINE.md

CORE_DOCTRINE remains the highest authority system inside FacelessOS.

No downstream module may override:

- realism doctrine
- trust preservation
- anti-slop doctrine
- continuity principles
- restraint principles

---

## COGNITION LOADING PHILOSOPHY

The kernel should load the minimum required cognition necessary to complete a task.

Do NOT load unnecessary systems.

The system prioritizes:

- context clarity
- routing precision
- modular stability
- orchestration cleanliness

over maximum simultaneous intelligence loading.

---

## LOAD ORDER

FacelessOS loads cognition in the following order:

1. CORE_DOCTRINE
2. CHANNEL_OVERLAY
3. WORKFLOW
4. ENGINES
5. EXECUTION_LAYER
6. PROJECT_CONTEXT

This order is mandatory.

---

## OVERLAY RESPONSIBILITIES

Overlays are responsible for:

- tone
- pacing
- emotional calibration
- audience psychology
- visual philosophy
- narrative pressure

Overlays do NOT control:

- workflow orchestration
- execution routing
- doctrine enforcement
- retrieval systems

---

## ENGINE RESPONSIBILITIES

Engines solve reusable editorial problems.

Examples:

- Human Texture Engine
- Narrative Engine
- Retention Systems

Engines should remain:

- modular
- reusable
- narrow in cognitive scope
- doctrine-compliant

---

## EXECUTION LAYER RESPONSIBILITIES

Execution layers optimize outputs for specific production environments.

Examples:

- Vidrush
- AI video systems
- Shorts workflows
- blog adaptation systems

Execution layers must preserve:

- retrieval safety
- realism
- documentary coherence
- visual specificity

Platform optimization must never override CORE_DOCTRINE.

---

## WORKFLOW RESPONSIBILITIES

Workflows define:

- orchestration order
- system activation sequence
- production stages
- editorial flow

Workflows should remain:

- deterministic
- modular
- stable
- reusable

The same workflow should support multiple overlays without identity collapse.

---

## ROUTING PRINCIPLES

The kernel should:

- load only necessary systems
- avoid context pollution
- prevent overlapping orchestration
- maintain cognitive clarity
- preserve identity stability

The kernel should avoid:

- unnecessary module loading
- giant orchestration chains
- redundant cognition
- conflicting instructions

---

## CONTEXT DISCIPLINE

FacelessOS treats context as a finite cognitive resource.

Large context windows should not justify:

- orchestration sprawl
- module duplication
- cognition overlap
- philosophical redundancy

The kernel should preserve:

- clarity
- precision
- routing simplicity

at all times.

---

## FAILURE PREVENTION

The kernel should actively prevent:

- identity drift
- emotional inflation
- abstraction drift
- retrieval collapse
- pacing instability
- overlay contamination
- doctrine violations

Stability is prioritized over generation aggression.

---

## MODULARITY PRINCIPLE

Every module should solve a specific editorial problem.

Avoid:

- mega-modules
- generalized intelligence blobs
- orchestration ambiguity
- unclear routing responsibilities

Small focused modules are preferred.

---

## IMPLEMENTATION PHILOSOPHY

FacelessOS evolves through implementation friction.

New systems should emerge ONLY when:

- workflows break
- routing becomes unstable
- retrieval fails
- overlays drift
- doctrine weakens
- continuity suffers

Avoid premature complexity.

---

## NON-NEGOTIABLE RULES

The kernel must never optimize toward:

- AI slop
- emotional manipulation
- incoherent automation
- context overload
- identity instability
- algorithmic sensationalism

Editorial coherence remains the highest orchestration priority.

---

## CORE KERNEL PRINCIPLE

The role of the kernel is not maximizing generation.

The role of the kernel is preserving stable editorial cognition during AI-assisted creation.
